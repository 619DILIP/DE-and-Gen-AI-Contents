## Description

- Combiner in Hadoop acts like a mini-reducer on the map side. It takes the intermediate data from the mapper and aggregates the mapper’s output locally (pre-reduces). 
- It not only reduces the overall time taken for sending data between mapper and reducer but also decreases the data that is required to process by the reducer.
- The use of combiner in-between mapper and reducer is optional and the unnecessary use of a combiner may cause expensive disk I/O. So, before using it, we have to make sure that we have enough resources in our system to handle all the combiner operations. 
- During the map job, the combiner can execute zero, one or more number of times and are independent of MapReduce. Also the number of combiner executions can vary depending on the size of data. 


## MapReduce job without Combiner 

- Let's say we have a text string as "hello hi hi hi hello hello hi" and we are using two mappers to process that string. So, when we send this string as input to mappers, the string data gets split into single word as key with their count value as 1. Then the mapper send this output result to the reducer which combines the same keys together and updates it frequency value. This example is shown in picture representation as below:

## MapReduce Job With Combiner 

- Let's say this time we have used combiner that will do the work of shuffling and sorting of output data from each mapper. It will combine the same keys just like reducer but for one mapper data only and then it sends the generated combined data from each mapper to reducer, which futhers do the shuffling and sorting operation. ## Implementation

- For this implementation, let's say we have a input file named as "input_file.txt" which has some text data. And now, we are interested in finding the frequency of each word of that input_file.txt file.
- For this, we will create a main program which will read our input file and then this file is sent to the mapper function, where each word is tokenized and stored as a <key, value> pair where the key will be the word itself and the value for each word will be assigned to 1. Then, the output of mapper function will be sent to combiner function, which will then combine identical words under the same key and update their counts. 
- For this mapper-combiner program, we use python language. 

**Map-Combine Program in Python** 

```python
import sys

def combiner(token):
    dict1 = {}
    value = 1
    for key in token:
        if key in dict1:
            value = dict1[key]
            dict1[key] = value + 1
        else:
            dict1[key] = 1
    
    return dict1


def mapper(data):
    token = [] 
    for word in data.split():
        token.append(word)
    
    return token

file = open("input_file.txt", "r")
read = file.read()
word = mapper(read)
word_combine = combiner(word)

output_file= open("file.txt", "w")
output_file.write(str(word_combine))

print("file written successfully")
sys.exit(1)

```
- Here, the output returned by the combiner function gets stored in the output file as "file.txt".

## Summary

- Combiners are just like reducers that works on the map side. They took the output of mapper and applies shuffling and sorting on the <key,value> pair. 
- They help in reducing the network congestion while transferring data from mapper to reducer. They are optional and are independent of map-reduce job. There is no guarantee that a combiner will execute for any given map task during map-reduce task. 
- Combiners if used efficiently will play key role in MapReduce and if not can cause the risk of expensive disk IO.

### Lecture Focus
This lecture is an opportunity to encourage associates to review their process for development. The Software Development Life Cycle (SDLC) can be approached from the question "How do you write software/ a program?" Encourage consideration of the requirements of a project, how functionality is confirmed, and how changes to the original requirements or design are accepted.

Phases of SDLC:

- Phase 1: Planning - This is conducted by the senior team members with inputs from all the stakeholders and domain experts in the industry. This stage gives a clearer picture of the scope of the entire project and the anticipated issues, opportunities, and directives which triggered the project.
- Phase 2: Analysis - There are generally five types of feasibilities checked:
    - Economic (Can we complete the project within the budget?)
    - Legal (Can we handle this project within existing laws?)
    - Operation feasibility (Can we handle supporting this system once it's built?)
    - Technical (Can current technologies handle creating or running this project?)
    - Schedule (Can we do this on time?)
- Phase 3: Design - There are two kinds of design documents developed in this phase:
    - High-Level which includes descriptions of different components and outlines of their functionality and relationships between different components.
    - Low-Level which can include functional logic for each component, details on data (like database table specs), expected input and output for the component.
- Phase 4: Coding/Building - The project is created.
- Phase 5: Testing - Testing can include unit and integration testing, but may also include user testing and feedback.
- Phase 6: Installation/Deployment - Commonly grouped with the Testing phase, deployment and integration can focus on the systems a new program is going to be used with, but can also include how users integrate the new program into their day-to-day workflow.
- Phase 7: Maintenance - Once deployed, the application must be maintained and supported.
